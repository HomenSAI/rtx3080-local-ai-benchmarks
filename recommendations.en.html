Recommended settings

Which model to use for which task, and how to set it up on one RTX 3080 (10 GB) with 32 GB RAM. Every number below comes from the tests in the report.

Claude Code

How these recommendations were made

The whole system was set up and run autonomously by an AI agent, Claude Code: it installed and configured the server, ran every test, found and fixed the problems, analysed the measurements and derived these settings. The author set the goals and rules and checked the conclusions.

Settings per model: optimal and maximum

Optimal is the live gateway profile: it passed the 95 % fill soak and keeps speed high. Maximum is the largest context that held 3 of 3 hidden facts at 80 % fill; speed is measured at that fill. Use the maximum only when you really need the longest input. Click a model: on the right you see its optimal and maximum mode and a ready fragment of the gateway configuration to copy; where to paste it is explained below.

How to use a copied fragment

  1. Open the folder of the server homensai-local-ai-lab on your computer and the file config/llama-swap.yaml in a text editor (Notepad or VS Code).
  2. In the section models: find the block with the model name (the first line of the fragment) and replace its cmd: line with the copied one. If the model is not in the file yet, paste the whole fragment under models:.
  3. Save the file and apply it: in the server folder open PowerShell (or the terminal in Docker Desktop) and run docker compose --profile gateway up -d --force-recreate --no-deps llama-swap-gateway.
  4. Check: the model is listed in the console 127.0.0.1:8766 and answers at 127.0.0.1:8080/v1. The model file (.gguf) must be in your model folder (MODEL_DIR); inside the container it is /models.

System settings (local machine)

  • GPU only. Keep weights and KV cache in the 10 GB of video memory, VRAM limit 9990 MiB. Modes with the KV cache in system RAM run at 1–3 tok/s.
  • One model at a time through the llama-swap gateway; idle models are unloaded after 15 minutes.
  • KV cache: q4_0 for long contexts (128K–262K), f16 when 64–128K is enough and speed matters, q8_0 in between.
  • Thinking off by default. Hybrid models otherwise spend the token budget on thinking and return empty answers; Bonsai loops.
  • Accelerators: use MTP (×1.34–1.44). Draft models slow generation down (×0.17–0.75) — do not use them.
  • Leave headroom: work at the context that passed the 95 % fill soak, not at the 80 % maximum.
  • Windows + WSL: .wslconfig memory=18GB, swap=4GB, autoMemoryReclaim=dropCache; keep 9–10 GB RAM for Windows; store models in a Docker volume on ext4 (loading from the Windows drive takes 6–14 min).
